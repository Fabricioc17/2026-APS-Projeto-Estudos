# 4.2.1 Levantamento de Requisitos

## Como os requisitos foram levantados

Os requisitos do StudyFlow foram levantados em três passos. Primeiro, realizamos uma **entrevista** com o Diretor Veiga, idealizador do projeto de reforço na escola, para entender sua rotina de apoio aos alunos. Depois, tivemos uma **conversa curta** com o estudante Leonardo, que está em recuperação em duas matérias, para ouvir as dificuldades de quem precisa organizar as tarefas e se preparar para o PSS. Por fim, fizemos a **análise de documento**: as fichas de papel e planilhas soltas que o diretor usa hoje para tentar controlar o desempenho de cada um.

O que está entre aspas na tabela a seguir foi dito textualmente por eles durante as conversas. A coluna da necessidade é a interpretação técnica do nosso grupo, que foi validada com o Diretor Veiga antes de ditar os requisitos finais.

❓ **A confirmar com o cliente:** O Diretor Veiga não soube precisar se o cronograma de reforço escolar deve ser aberto para toda a escola ou restrito por turma. Adotamos temporariamente a visibilidade por turma para seguir com a modelagem, e a pergunta fica anotada aqui como pendência.

## Da fala à necessidade

| # | Fala | O que é | Necessidade por trás |
|---|---|---|---|
| F1 | "Queria um sistema com um painel bem visual e moderno para os alunos entrarem e verem as coisas." (Diretor Veiga) | solução | os estudantes centralizarem a gestão de suas pendências sem depender de avisos no pátio |
| F2 | "Todo dia preciso procurar os alunos para avisar o horário do reforço e quais tarefas precisam entregar." (Diretor Veiga) | necessidade | publicação digitalizada de cronogramas e agendas de atendimento pedagógico |
| F3 | "Acompanhar tudo isso na mão é cansativo demais, às vezes me perco em quem precisa de atenção urgente." (Diretor Veiga) | **necessidade implícita**: ele relatou cansaço | indicador visual ou alerta de criticidade automático para alunos com alto risco de reprovação |
| F4 | "Fico perdido procurando o que cai no PSS e quais tarefas da semana eu preciso entregar." (DIRETOR VEIGA) | necessidade | repositório organizado de conteúdos do PSS e checklist semanal de atividades pendentes |

## Histórias de usuário

| # | História de usuário | Veio de |
|---|---|---|
| HU01 | Como **diretor**, quero **visualizar os alunos com notas vermelhas**, para **identificar rapidamente quem precisa de apoio pedagógico urgente**. | F3 |
| HU02 | Como **diretor**, quero **publicar cronogramas de reforço**, para **que os estudantes saibam os horários e salas sem eu precisar procurá-los**. | F2 |
| HU03 | Como **aluno**, quero **acessar os materiais de estudo do PSS**, para **me preparar para as provas de forma organizada e direcionada**. | F1, F4 |

## Requisitos funcionais

| # | Nome | Requisito | Veio de |
|---|---|---|---|
| RF01 | Registrar aluno | O sistema deve permitir que o diretor cadastre os estudantes e suas respectivas turmas. | Base do sistema / HU01 |
| RF02 | Lançar notas | O sistema deve permitir que o diretor lance e atualize as notas de recuperação dos alunos. | HU01 e F3 |
| RF03 | Publicar cronograma ❓ | O sistema deve permitir que o diretor poste cronogramas de reforço. *(❓ A confirmar: visibilidade geral ou por turma).* | HU02 |
| RF04 | Hospedar material | O sistema deve permitir que o diretor realize o upload de arquivos de estudo voltados ao PSS. | HU03 |
| RF05 | Listar tarefas | O sistema deve permitir que o aluno visualize o checklist de suas atividades pendentes na semana. | HU04 |
| RF06 | Sinalizar criticidade | O sistema deve emitir um destaque visual na listagem para alunos com mais de duas notas vermelhas. | F3 (Necessidade implícita) |
| RF07 | Gerenciar disciplinas | O sistema deve permitir o cadastro e vínculo das matérias escolares (Matemática, História, etc.). | Buraco encontrado na conferência |

## Conferência com a 4.1

| Item do escopo (4.1) | Requisitos |
|---|---|
| O diretor acompanha de perto os alunos que precisam de ajuda. | RF01, RF02, RF06 |
| O diretor posta cronogramas de reforço escolar. | RF03 ❓ |
| O sistema centraliza materiais de estudo e conteúdos do PSS. | RF04 |
| Os estudantes consultam tarefas e organizam sua rotina. | RF05 |

**Toda história tem requisito.** HU01 virou o RF02, HU02 o RF03, HU03 o RF04 e HU04 o RF05. 

**Todo requisito tem origem.** Dois itens não vieram diretamente de histórias transcritas: o RF01 é a premissa técnica básica para o painel existir, e o RF06 nasceu da interpretação técnica da dor relatada na fala F3. Ambos estão devidamente mapeados com suas origens na tabela.

**O que a conferência mudou.** A nossa proposta de escopo original na 4.1 focava em "postar notas" e "centralizar materiais", mas ao cruzar os dados nesta tabela de conferência, percebemos um erro crítico: o sistema não teria como organizar o repositório ou o boletim porque nós havíamos esquecido de mapear uma funcionalidade para cadastrar as matérias da escola. Por causa desse buraco descoberto na conferência, incluímos emergencialmente o **RF07 (Gerenciar disciplinas)** para sustentar o banco de dados. A seção fecha com sete requisitos funcionais e três não funcionais, respeitando o teto exigido.
